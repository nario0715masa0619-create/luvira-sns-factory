# Evaluation Rule

## Primary KPI

### 投稿から 24 時間後のインプレッション数

- 勝敗はこれで決める。
- 投稿時刻を正確に記録し、24 時間後（±30 分）に数値を取得する。
- 複数投稿の比較では、平均 24h インプレッション数を基本とする。

## Secondary KPI

| KPI | 説明 | 測定方法 |
|-----|------|----------|
| 人間採用率 | 生成案のうち、人間が承認して投稿した割合 | 承認数 / 提案数 |
| 人間修正時間 | 提案から承認までの時間 | タイムスタンプ記録 |
| 生成コスト | 1 案あたりの推論コスト | モデルのトークン単価 × 使用量 |
| いいね数 | 投稿後のいいね数 | プラットフォームの数値 |
| リプ数 | 投稿後のリプライ数 | プラットフォームの数値 |
| プロフィール遷移 | プロフィールクリック数 | プラットフォームの数値 |
| パクリ感の少なさ | 元バズ投稿との類似度の主観評価 | 1-5 の評価（5 が最もオリジナル） |
| ブランド適合度 | クライアントブランドとの整合性 | 1-5 の評価（5 が最も適合） |
| account_type 適合性 | `personal` / `corporate` の投稿先アカウント種別に適しているか | 1-5 の評価（5 が最も適合） |
| 別ジャンルへの再現性 | 同じ構造が他業種でも使えるか | 1-5 の評価 |

## account_type 別の評価観点

### personal

- **共感度**: ターゲットの日常課題・本音に寄り添っているか
- **リプ誘発力**: 経験募集・問いかけ・議論を促す CTA になっているか
- **本音感**: 機械的ではなく、人間らしい問いかけ・仮説トーンか
- **虚偽体験の有無**: 捏造された実体験・実績がないか
- **体験・伝聞匂わせ表現の有無**: 「個人的な話だけど」「知り合いの会社で」「友達の現場で」など、確認不能な経験談を匂わせる表現がないか
- **類似性**: 元投稿のフレーズを流用していないか
- **リスト構造残留の少なさ**: corporate 由来の「3 つ」「3 点」「チェック項目」型リスト構造が残っていないか
- **入口表現の自然さ**: 法人告知調ではなく、個人の観察・仮説・違和感から自然に入っているか
- **商材接続の軽さと自然さ**: 押し売りにならず、「〜かもしれない」「〜な気がする」などの仮説表現で軽く接続しているか

### corporate

- **信頼性**: 客観的・安心感のある表現になっているか
- **保存性**: ノウハウ・チェックリスト・資料として保存されやすいか
- **問い合わせ導線**: 無料相談・資料請求・チェックリストなどの CTA になっているか
- **ブランド毀損リスク**: 攻撃的・煽情的・過度な保証表現がないか
- **一人称体験談の不自然さ**: 「僕も」「私も」などの個人体験調が使われていないか
- **実務チェック項目の具体性**: セキュリティ診断等の場合、古い権限・未使用アカウント・API キー・外部連携など、実務で確認すべき項目が具体的に示されているか
- **根拠不明表現の少なさ**: 「当社の調査では」「導入実績では」「多くの企業で」など、根拠のない調査風・実績風表現が含まれていないか
- **フックの具体性**: 抽象的な不安ではなく、権限・API キー・外部連携・Tool 権限・Connector・未使用アカウント・説明責任など、具体的な実務論点がフックに含まれているか
- **方向性の多様性**: チェックリスト型・リスク棚卸し型・説明責任・レポート型など、複数の切り口が提案されているか
- **元フックからの距離**: 元バズ投稿の personal 向けフック（「痛い目」「本番で」「失敗して気づいた」等）がそのまま残っていないか
- **corporate→corporate 結果への単純収束回避**: personal → corporate の結果が、元々 corporate 向けの結果とほぼ同じ構成に単純収束していないか

## Cross 変換時の追加評価観点

`source_account_type` ≠ `account_type` の場合、以下も評価する。

- **変換の完全性**: 変換元の構造（個人の失敗談・本音・リプ誘導、法人の啓発構造・実務フック）が変換先にふさわしく変換されているか。
- **企業版一人称体験の排除**: personal → corporate で「当社も」「当社でも」「弊社も」「弊社でも」など、個人構造の単なる置換が残っていないか。
- **CTA 変換の適切さ**: personal のリプ募集CTAが corporate ではチェックリスト・無料相談・資料請求・問い合わせ導線に変換されているか、またはその逆が適切に行われているか。
- **感情フックの再構成**: personal の本音・煽り・感情表現が、corporate では実務フック（見落とし・後回し・属人化・棚卸し不足・説明責任）に変換されているか。
- **保存性から議論性への変換**: corporate の保存性・チェックリスト性が、personal では問いかけ・仮説・議論誘発に変換されているか。
- **体験・伝聞匂わせの排除**: corporate → personal で「個人的な話だけど」「知り合いの会社で」「友達の現場で」などの確認不能な経験談を匂わせる表現が出ていないか。
- **商材接続の維持**: corporate → personal で、個人向けだからといって商材接続が完全に消えていないか。軽く自然に残っているか。
- **収束の回避**: personal → corporate の結果が corporate→corporate の結果とほぼ同じになっていないか。ただしこれは悪ではなく、Cross 変換の検証として記録する。

## 比較実験の評価

### Claude SNS Engine vs Kimi K2.7 Low-Cost SNS Factory

詳細は `docs/experiment-design.md` を参照。

#### 勝者条件

1. **平均 24h インプレッション数が高いチームを勝者とする。**
2. 平均が同程度の場合、最大 24h インプレッション数を参考指標とする。
3. それも同程度の場合、生成コストと人間修正時間が少ない方を勝者とする。

## 継続改善ルール

- 24 時間後の数値を必ず記録する。
- 上位案と下位案の差分を分析する。
- 構造・フック・感情分類のどこが効いたかを検証する。
- 次回のプロンプト改善に反映する。

## 測定時の注意

- 投稿後の追加拡散（リポスト、宣伝等）は行わない。
- 比較対象は同じアカウント・同じジャンル・近い時間帯とする。
- 画像条件、ハッシュタグ数、リンク有無を統一する。
- インプレッション数は各プラットフォームの公式数値を使用する。
