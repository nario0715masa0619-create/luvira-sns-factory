# Phase 2-F Approval Package Generator

## 1. Executive Summary

Phase 2-F implements a helper that reads the outputs of Step 09 (Market Judge) and Step 10 (Final Packager), then generates the human approval package.

The generator is implemented as a Python script:

- `scripts/approval_package_generator.py`

It creates/updates:

- `runs/{run_id}/final-candidates.md`
- `runs/{run_id}/approval.md`
- `runs/{run_id}/run.json` (status and selected_candidate_id only)

This script does **not** execute prompts, integrate with APIs, or post automatically. It only formats existing step outputs into a consistent approval package.

---

## 2. Scope

### In Scope

- Read `step-09-market-judge.md` and `step-10-final-packager.md`
- Extract top 5 candidates, scores, and recommended candidate
- Generate `final-candidates.md`
- Update `approval.md` placeholders for final candidates, recommended candidate, and market judge summary
- Update `run.json` status to `pending_approval` and set `selected_candidate_id`
- Support `--dry-run`

### Out of Scope

- Prompt execution
- AI API integration
- SNS API integration
- n8n integration
- Automatic posting
- Automatic approval
- Modifying Risk Review, Similarity Review, Account Type Fit, or CTA Fit decisions (human input required)
- Modification of `prompts/`, `experiments/phase-1/`, or Phase 1 assets

## 5. Output Files

### `final-candidates.md`

Contains:

- Run information
- Top 5 final candidates with full text
- Market scores and judge comments
- Recommended candidate with selection reason and expected reaction
- Complete market judge score table

### `approval.md` Updates

The following sections are updated:

- **Final Candidates** — candidate texts 01-05
- **Market Judge Summary** — scores, comments, and selected flag
- **Recommended Candidate** — heading, text, and selection reasons
- **Market Judge Summary Notes** — brief auto-generated summary

The following sections remain as human-review placeholders:

- Similarity Review
- Risk Review
- Account Type Fit
- CTA Fit
- Human Approval Decision
- Pre-Post Checklist
- Posting Record
- 24h Metrics Record

### `run.json` Updates

- `status`: `pending_approval`
- `current_step`: `step-10-final-packager`
- `selected_candidate_id`: `candidate-XX`
- `updated_at`: current timestamp

## 6. Parsing Strategy

The generator uses flexible regex parsing to tolerate minor format variations.

### Step 09 Parsing

- Extracts `account_type` and `desired_cta_style` from the header section
- Parses the score table by splitting pipe-delimited rows
- Parses top 5 list ordered by rank
- Parses recommended candidate number, text, and reason

### Step 10 Parsing

- Extracts `account_type` and `source_account_type`
- Parses top 5 detailed blocks using `### 案 N（推奨順位: N）` headings
- Parses recommended candidate block including adoption reason and expected reaction

### Merge Logic

- Candidate numbering follows Step 09 ranking (01 = rank 1, 02 = rank 2, etc.)
- Full candidate text is taken from Step 10 if available; otherwise from Step 09
- Selection reason prefers Step 10 adoption reason; falls back to Step 09 selection reason
- Expected reaction is taken from Step 10
- Market scores and judge comments are taken from Step 09

---

## 7. Validation Rules

1. Run folder must exist under `runs/`.
2. `step-09-market-judge.md` must exist.
3. `step-10-final-packager.md` must exist.
4. `templates/final-candidates.md` must exist.
5. `approval.md` must exist in the run folder.
6. If parsing fails to find top 5 candidates, the script exits with an error.
7. If parsing fails to find a recommended candidate, a warning is printed but generation continues.

---

## 8. Safety / Governance

- **No automatic approval.** Human Approval Decision checkboxes remain unchecked.
- **No automatic posting.** The script only creates/updates files.
- **Risk Review remains pending.** All risk rows stay `pending` until a human updates them.
- **Existing files are overwritten.** Re-running the generator regenerates the package from the latest step outputs.
- **No AI execution.** The script does not call any model or API.

## 12. Known Limitations

1. **Markdown format sensitivity.**
   - The parser expects Step 09/10 outputs to follow the documented prompt formats. Heavy deviations may cause extraction failures.

2. **Risk Review remains manual.**
   - Step 08 Risk Filter output is not automatically parsed. Humans must update risk levels.

3. **Similarity Review remains manual.**
   - Step 07 Similarity Guard output is not automatically parsed.

4. **Account Type Fit and CTA Fit remain manual.**
   - These require human judgment.

5. **No automatic posting.**
   - Posting Record and 24h Metrics Record remain placeholders until after posting.

6. **Expected reaction is optional.**
   - If Step 10 does not include `**予想される反応:**`, the field is left blank.
