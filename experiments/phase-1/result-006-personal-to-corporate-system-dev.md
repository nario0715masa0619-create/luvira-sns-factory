## 01 Pattern Miner 出力

```markdown
### 元投稿の構造パターン
- 個人の気づき/違和感から入るフック
- 「〜が怖い」「〜が増えてて」という感情表現
- 半年前に関わった現場、という個人経験の提示
- 具体的事象：要件整理があやふや → AIに実装させる → 仕様変更が雪だるま式 → 納期遅延
- 仮説/教訓：MVPと本開発の区別がついてないと、AIの速さが手戻りの速さになる
- 読者への問いかけ：みんなの現場ではどうやってスコープを区切ってる？
- CTA：リプで教えてほしい

### 感情ドライバー
- 共感：AI開発のトラップ感
- 不安：手戻り、納期遅延、技術負債
- 議論志向：他者の実践を聞きたい

### 転用先商材に適した構造
- AI活用型短納期システム開発
- 元の「個人の違和感」を「組織的課題提起」に変換
- 元の「半年前に関わった現場」を「よくある見落とし」に変換
- 元の「MVPと本開発の区別」はそのまま corporate 向け実務論点として活用可能
- 元の「スコープ区切りの問いかけ」を「チェックリスト・資料請求・無料相談CTA」に変換

### 再利用可能なフレーム
1. 課題提起：AI活用型短納期開発で起こりやすい認識ズレ
2. よくある見落とし：要件整理、スコープ管理、MVP切り分け
3. 整理すべき論点：レビュー体制、承認ゲート、仕様変更の扱い、技術負債
4. サービス接続：チェックリスト・相談・資料請求

### セキュリティ診断論点の混入リスク
- 元商材がセキュリティ診断ではないため、権限設計・APIキー・外部連携等の論点は個人投稿にも含まれていない。
- 転用時にこれらを持ち込まないよう注意する。
```

## 改善すべき prompt

1. **05 Variation Generator**: 数字のバリエーションをさらに明示。「確認したい項目」「整理すべき観点」「棚卸し」以外にも「見直しポイント」「合意事項」「判断基準」等を指示。
2. **06 Hook Specialist**: 第2商材固有のフックパターン（受託開発・納品後運用・品質管理・責任分界）をさらに例示し、商材切り替え時の具体名詞選択を支援する。
3. **07 Similarity Guard**: 「確認したい項目」「見落とされがち」などの定型表現が複数案で重複する傾向を、多様性コメントとして軽く警告する基準を追加。
4. **08 Risk Filter**: 保守的な表現（「抑える」「整える」）が効果保証（「防げます」「解決します」）に誤変換されないよう、接続先のNGフレーズを追加。
5. **09 Market Judge**: 商材接続の具体性を採点基準に追加。第2商材では「レビュー体制」「承認ゲート」などの実務論点が含まれているかを評価。
