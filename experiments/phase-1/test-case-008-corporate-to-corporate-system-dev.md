## 元サンプル投稿（架空の法人アカウント風）

AI活用型短納期開発では、実装のスピードが向上する一方で、
要件整理やスコープ管理の認識ズレが課題になることがあります。

特に、MVPと本開発の範囲が明確でない場合、
仕様変更の影響が大きくなり、納期や品質に影響が及びやすいです。

効果的な進め方として、以下を事前に整理することをおすすめします。
- 要件整理の完了基準
- MVPと本開発の切り分け
- AIコード生成のレビュー体制
- 人間承認ゲートの設計
- 仕様変更時の対応ルール

詳細なチェックリストは資料請求でお送りします。

## same-type 変換時の構造維持
- source_account_type と account_type が同じ corporate のため、法人向けの信頼性・保存性・実務性を維持する
- 課題提起 → 確認項目 → 解決の方向性 → CTA の構造を維持
- 「当社も失敗しました」「弊社でも経験しました」等の企業版一人称体験は避ける
- 根拠不明な実績表現、効果保証、誇大広告、過度な煽りは禁止

## 変換ルール
- source=corporate / account=corporate のため、法人向けの客観的・信頼的トーンを維持
- 課題提起 → 確認項目 → サービス接続 → CTA の構造を維持
- 具体論点を1〜3個程度列挙し、保存性を高める
- CTAは checklist / consultation / document_request に寄せる
- 「資料請求はこちらから」「無料相談受付中です」「チェックリストはプロフィールリンクから」等を使用
- ただし、企業版一人称体験（「当社も」「弊社も」）は避ける
- 根拠不明な実績表現は避ける
- 効果保証・煽情表現は避ける

## 禁止表現
- 「必ず短納期で完成します」
- 「AIで開発コストを大幅削減できます」
- 「失敗しません」
- 「炎上しません」
- 「品質を保証します」
- 「完全に任せられます」
- 「当社も経験しました」
- 「弊社でも失敗しました」
- 「導入企業では必ず成果が出ています」
- 「多くの企業で成功しています」
