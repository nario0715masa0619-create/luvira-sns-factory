## 元バズ投稿（架空サンプル）

```text
セキュリティ対策って、本番で痛い目を見るまで後回しにしがちですよね。

僕も半年前、小さな設定ミスを見落としていました。
気づいたのは、週次のちょっとした確認の時間だったんです。

「これ、本番で起きたら大変だ」
その一念で見直したら、意外なところにリスクが眠っていました。

小さな確認が、大きな事故を防ぐ。
その積み重ねが、セキュリティの土台になります。

みなさんの現場で、見落としがちな設定ってありますか？
リプで教えてください。
```

## 投稿元プラットフォーム

X（旧 Twitter）

## 投稿元業種

IT / セキュリティ

## 投稿元ジャンル

働き方 / 業務改善 / 個人発信

## 推定された伸びた理由

- **共感**: 「セキュリティ対策を後回しにしがち」という多くの IT 担当者の共通課題を提起している。
- **感情移入**: 投稿者自身の失敗談を一人称で語ることで、読者が体験を借りて感じられる。
- **議論**: 最後に「見落としがちな設定」をリプで募り、関与を促している。
- **UGC**: 失敗談のフォーマットが、読者の「自分もあるある」を呼び起こす。

### 投稿目的

AI エージェントによる継続的なセキュリティ診断サービスの認知獲得と、無料相談・資料請求・チェックリスト DL などの問い合わせ導線獲得。

### desired_cta_style

`checklist` / `consultation` / `document_request`

法人アカウントとして、具体的な次のアクション（資料請求・無料相談・チェックリスト取得）を提示する。

### allowed_persona_expression

`当社 / 弊社 / 主語省略`

法人アカウントなので、一人称体験談は避け、客観的・組織的な視点を基本とする。

### risk_tolerance

`conservative`

法人ブランドを守るため、保証表現・誇大表現・過度な煽り・個人体験談を厳格に禁止する。

### NG 表現

- 「最安値」
- 「絶対」
- 「誰でも」
- 「完全」
- 「100%」
- 「一切」
- 「漏洩しない」
- 競合他社の否定的な言及
- 具体の顧客名・案件名
- 虚偽の実体験・確認不能な実績
- 過度な不安喚起・煽情表現
- 「僕も」「私も」「自分も」等の一人称体験調
- 「リプで教えてください」等の personal 向け CTA

### 口調

客観的・信頼的な法人トーン。課題提起と解決価値を整理し、押し売り感を出さない。個人の体験談は避け、組織としての知見・ノウハウ・チェックリストを重視する。

### 備考

- 本 test-case は `source_account_type=personal` → `account_type=corporate` の cross 変換検証用である。
- 個人発信者の本音・失敗談・一人称表現を、法人アカウント向けの客観的・信頼的な表現に変換する必要がある。
- 転用後の構造目標: 課題提起 → よくある見落とし → チェック項目 → 診断で見える化できること → CTA。
- 個人の熱量は、法人向けには実務課題・確認項目・保存性へ変換する。
- 医療・金融等の特定業規制を受ける業種を対象にしない。
- 具体の顧客事例や数値は入れない。
- 商品の価格や割引は今回言及しない。
- AI エージェントの能力を過剰に謳わない。
- 機密情報を含めない。
