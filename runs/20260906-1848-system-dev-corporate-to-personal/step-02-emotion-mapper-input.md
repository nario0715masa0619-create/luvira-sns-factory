### 元投稿概要

### アカウント種別判定

- source_account_type: corporate
- 判定理由: 業界課題を構造化し、専門用語とチェックリストを使って信頼性を訴求。最後に資料請求/相談予約CTAで自社サービスに誘導している。
- account_type との差異: source は企業権威と情報提供、target は個人の体験・気づき・リプ誘発。
- 転用時の調整ポイント:
  - 会社視点の「業界課題」→ 個人の「現場で困ったこと」
  - チェックリスト形式 → 自分語り + 気づき + 軽い問いかけ
  - 資料請求CTA → 返信・議論・体験共有CTA

### セクション分け

1. **フック**: 業界共通の落とし穴を数字や事例で提示
   - 役割: 読者の不安や関心を引き出す
2. **問題**: なぜその課題が起きるかを構造化
   - 役割: 共感と「自分も当てはまる」感を生む
3. **チェックリスト**: 読者がすぐ使える確認項目
   - 役割: 保存・ブックマーク欲を誘発
4. **解決方向性**: 専門的なアプローチを提示
   - 役割: 信頼性を高め、専門家としての価値を示す
5. **CTA**: 資料請求や相談への誘導
   - 役割: 関心を商談導線に繋げる

### 情報配置の順序

1. 共感を誘発する課題提示
2. 不安を深める原因分析
3. 自己診断できるチェックリスト
4. 専門家からのアドバイス（解決方向性）
5. 次のアクションCTA

### 反応設計

- **共感**: 「うちもそうだった」「自分もやりそう」という感情を課題提示で誘発
- **保存欲求**: チェックリストで「後で見返したい」と思わせる
- **信頼**: 専門的な解決方向性で「この人に相談したい」と思わせる
- **行動**: CTAで資料請求や相談予約へ誘導

### 使用技法

- **問いかけ**: フックで読者を引き込む
- **対比**: 理想と現実のギャップを示す
- **列挙**: チェックリスト形式で具体性を出す
- **具体例**: 業界のよくある失敗例を挙げる
- **権威付け**: 専門用語やフレームワークで信頼性を担保

### 構造の要約

法人アカウント向けの「不安喚起 → 共感 → 自己診断 → 専門家アドバイス → 商談CTA」構造。
専門性と実用性のバランスが取れており、読者は「課題を理解し、自分ごと化し、保存し、専門家に相談したい」と導かれる。

## Prompt To Apply

Apply the following prompt to the Source Input above.

## Role

Emotion Mapper（感情分類 AI）

## Objective

Pattern Miner が抽出した構造をもとに、その投稿が何の感情・行動ドライバーで伸びたかを分類する。

## Inputs

- Pattern Miner の構造分析
- 元バズ投稿（全文）
- `account_type`: 転用先アカウントの種別（`personal` / `corporate`）
- いいね・リプ・保存・シェアの傾向（あれば）

## Process

1. 構造の各セクションが読者に与える感情を特定する。
2. 以下の観点で分類する：保存・共感・議論・意外性・覚悟表明・UGC。
3. 主要な感情ドライバーを 1〜3 個選ぶ。
4. 読者心理の遷移を時系列で整理する。
5. 各感情がどのセクションで最も強く生まれているかを記録する。
6. `account_type` に適した反応設計かどうかを評価する。
   - `personal`: 共感・議論・本音・体験共有を重視。
   - `corporate`: 保存・信頼・問い合わせ導線・ノウハウ性を重視。
7. `account_type` に対して不自然な感情導線があれば警告する。

## Do Not

- 数値の根拠なき拡大解釈をしない。
- 元投稿の感情を過剰に美化しない。
- 推測を断定で書かない。
- クライアント情報をここでは扱わない。
- `account_type` 未指定のまま感情評価を進めない。

- [ ] 各感情がどのセクションで生まれているか明確

- [ ] 強度は 1-5 の数値で示されている
- [ ] 元投稿の内容を再現せず、分析のみを行っている
- [ ] `account_type` に適した反応設計か評価されている
